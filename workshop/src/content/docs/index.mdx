Welcome to the Building a multi-agent application with Microsoft Agent Framework (MAF) and Microsoft Foundry.

In this workshop we're going to build an _interview coach_ application that is composed of 5 agents. We'll use Microsoft Agent Framework to run the interview agents in .NET and Foundry to host their model.

In the finished app, a triage agent routes us to a receptionist agent, behavioural and technical interviewer agents, and a summarize agent.

We'll use Microsoft Agent Framework to create the interview coach's agents and Foundry to host their model. The finished coach has five roles: triage, receptionist, behavioural interviewer, technical interviewer, and summariser. We'll build a single coach first, give it the tools it needs, then divide the interview into those specialist roles.

This workshop contains both the finished app, and a starter Aspire application that we'll use to build the lessons with. A Blazor chat interface is already included in the Aspire app, so that gives us somewhere to try each agent change as we make it.

## Why use more than one agent?

Document intake needs a parser and instructions about collecting information. A technical interviewer needs the saved context and instructions about asking useful questions. Giving those jobs separate agents lets us adjust one role's prompt and tools without rewriting the others.

However, that separation adds work: we have to decide who takes the next turn and carry the interview context between roles. We'll first build a single coach that handles the whole interview, then split the responsibilities.

## The workshop's format

We'll use the Microsoft Agent Framework and its `ChatClientAgent`. Give it coaching instructions, and stream its replies into the chat page. Then we'll write a C# tool and connect services through Model Context Protocol (MCP) so the coach can save records and read documents. Finally, we'll build the handoffs and investigate a failed tool request.

To help speed development, each chapter specifies the files to edit and gives us something specific to try. All while working in the same project. Checkpoint downloads will be available at the end of each chapter if want a fresh starting point or a comparison with your code.
