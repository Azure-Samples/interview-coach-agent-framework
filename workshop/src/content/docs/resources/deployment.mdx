Deployment is optional after the completed capstone. Azure Container Apps hosts the existing .NET services; the agents continue to execute in `InterviewCoach.Agent`.

**Use an approved, access-restricted development environment with fictional data.** Review [development endpoints, record access, and upload retention](../../reference/deployment/#review-access-and-data-handling) before exposing the app.

## Check the deployment entry point

Finish the [capstone's required `08-complete-support.patch` step](../../workshop/13-capstone/) first. It restores the completed deployment AppHost and removes temporary workshop support. Until then, the learner's project-based AppHost stays in its starter state.

In the completed project, `azure.yaml` targets `src/InterviewCoach.AppHost/InterviewCoach.AppHost.csproj`. Configure that project's `appsettings.json` for deployment. See [entry-point details](../../reference/deployment/#check-the-deployment-entry-point).

The learner checkpoint keeps Foundry reuse enabled. Supply the same four `MicrosoftFoundry:Existing` identifiers to the deployment entry point's configuration; its configuration is separate from the root file-based AppHost. Review the existing model's access for the deployed identity. See [existing Foundry resources](../../reference/providers/microsoft-foundry/#reuse-an-existing-account-and-deployment).

## Provision an approved development environment

Follow the [deployment commands and account checks](../../reference/deployment/#provision-an-approved-development-environment). Confirm the selected subscription, region, model access, capacity, and cleanup owner before `azd up`.

## Check the deployed application

Run the capstone's short synthetic interview and inspect its tool calls and saved summary. The [deployment checklist](../../reference/deployment/#check-the-deployed-application) covers service connectivity, identity, and failure diagnosis.

## Remove only the resources you own

For a running local AppHost, run this from the folder that started it:

<Tabs syncKey="shell">
<TabItem label="Bash">

```bash
aspire stop --apphost ./apphost.cs
```

</TabItem>
<TabItem label="PowerShell">

```powershell
aspire stop --apphost ./apphost.cs
```

</TabItem>
</Tabs>

**Cloud resources remain until cleanup.** The example and learner share the Chapter 0 Foundry account and deployment. Keep them until both projects are finished. Review any separate `azd` environment too; never assume its cleanup command owns the shared model. Follow the [cleanup reference](../../reference/deployment/#remove-only-the-resources-you-own) to review each scope and remove only owned resources.
