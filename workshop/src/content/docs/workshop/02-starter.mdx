## What we are doing

Start the supplied application shell. The UI deliberately says that coaching is not connected. You are not beginning with a completed agent and changing its greeting.

## Why supply the plumbing?

The learning goal is Agent Framework and Foundry, not recreating a Blazor chat interface or writing an EF Core repository. The archive includes these application parts so each later lesson can focus on a small agent-related decision.

Some projects and packages are present before they are used. Presence in the solution does not mean the AppHost starts that service.

## How and where

### 1. Download and extract the starter

<Checkpoint stage="02-starter" />

Extract the archive into a new directory such as `interview-coach-lab`. Open that directory in your editor. You should see `InterviewCoach.slnx`, `apphost.cs`, and `src/` at the same level.

### 2. Locate your working files

| File or directory | Its responsibility |
| --- | --- |
| `src/InterviewCoach.Agent/Program.cs` | Service startup, dependencies, and HTTP endpoints |
| `src/InterviewCoach.Agent/AgentDelegateFactory.cs` | Agent definitions and workflow construction |
| `src/InterviewCoach.WebUI/` | Supplied chat UI and AG-UI client |
| `src/InterviewCoach.Mcp.InterviewData/` | Supplied persistence plumbing and session tools, introduced later |
| `apphost.cs` | Local service graph and resource references |
| `apphost.settings.json` | Model provider and agent-mode configuration |

The starter's single-agent and handoff factories explicitly reject use until their lessons are implemented. The placeholder UI prevents a chat request from being mistaken for a successful agent response.

### 3. Run the shell

From the extracted project root:

```sh
aspire start --apphost ./apphost.cs
```

Use the dashboard URL printed in the terminal. Wait for `agent` and `webui`, then open the `webui` endpoint. Do not guess the port.

## See it work

The page says **Your application shell is running** and **Coaching is not connected yet**. There should be no Foundry model, MarkItDown, or Cosmos resource in this stage's running graph.

If the first run prompts you to provision Foundry, stop and confirm you extracted checkpoint `02-starter`, not a later checkpoint or the repository's final application.

## Make it yours

Change the placeholder heading in `src/InterviewCoach.WebUI/Components/Pages/Chat/Chat.razor`, rerun, and confirm it appears. Then identify which file should change to add an agent rather than merely change the UI.

## If you get stuck

Check that you are in the extracted directory containing `apphost.cs`. A restore failure concerns package availability. A launch failure concerns process startup. Neither means the placeholder coach needs a different prompt.

## Carry forward

The next lesson activates the supplied model/AG-UI startup and replaces the unimplemented single-agent factory with a real coach. Keep this folder; recovery downloads always go into a different one.
