Your application now has the complete interview workflow. Run a short interview through the WebUI. Your result is one saved record containing the materials, answers, and final feedback.

Continue in the same `interview-coach-lab` project from the previous chapter. No further code changes are needed. Keep `WorkshopHosting.cs` and the MCP discovery probe in place. Keep your `Single` agent available for comparison with the handoff workflow.

## Run a short interview

From the working project root, stop the previous run, build, and start with your existing approved model configuration:

<Tabs syncKey="shell">
<TabItem label="Bash">

```bash
aspire stop --apphost ./apphost.cs
dotnet build InterviewCoach.slnx
aspire start --apphost ./apphost.cs -- --provider MicrosoftFoundry --mode HandOff
```

</TabItem>
<TabItem label="PowerShell">

```powershell
aspire stop --apphost ./apphost.cs
dotnet build InterviewCoach.slnx
aspire start --apphost ./apphost.cs -- --provider MicrosoftFoundry --mode HandOff
```

</TabItem>
</Tabs>

Open the dashboard's WebUI endpoint, start a new chat, and send:

```text
Run a short practice interview with these fictional materials.
Resume: https://codemillmatt.github.io/interview-coach-agent-framework/samples/resume-peter-parker.pdf
Job: https://codemillmatt.github.io/interview-coach-agent-framework/samples/jd-cloud-solution-architect.pdf
Read and save both documents. Let's do one question per interview phase.
```

Answer the behavioural question with a fictional example, ask to move to technical practice, and answer that question. Then ask for a saved summary and completion.

## Keep the result and stop the app

Copy the **Session ID** shown above the conversation. Open that record in Cosmos Data Explorer under `interviewdb` / `interviewsessions` and check:

- `id` matches the WebUI session ID.
- Both document text fields contain the supplied materials.
- `Transcript` contains your answers, feedback, and saved summary without duplicated earlier exchanges.
- `IsCompleted` is `true`.

Keep the ID for later lookup. Then stop the local application:

<Tabs syncKey="shell">
<TabItem label="Bash">

```bash
aspire stop --apphost ./apphost.cs
```

</TabItem>
<TabItem label="PowerShell">

```powershell
aspire stop --apphost ./apphost.cs
```

</TabItem>
</Tabs>

Compare your resource inventory for the example and learner folders. Stopping Aspire leaves cloud resources in place. Remove only resources you own and no longer need; use the <a href={siteLink('resources/deployment/')}>deployment and cleanup guide</a> to check ownership and scope.

Keep development endpoints private and use fictional data. Public deployment requires an access-control and data-retention review.
