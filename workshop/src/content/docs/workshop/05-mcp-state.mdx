## What we are doing

Connect the coach to a separate MCP server that creates, reads, updates, and completes interview records. The supplied repository stores those records in the local Cosmos emulator.

## Why separate tools and state?

MCP gives the agent a standard way to discover and invoke tools owned by another service. It does not replace your repository, authenticate every user automatically, or turn every record into model memory.

There are three different kinds of state here: the UI's message list, the agent conversation context, and the persisted interview record. Saving one does not automatically restore the others.

## How and where

### 1. Inspect the supplied data contract

Open `src/InterviewCoach.Mcp.InterviewData/InterviewDataDbContext.cs` and locate `InterviewSession`. Follow the ID, resume/job-description fields, transcript, and completion flag.

Then read `InterviewSessionRepository.cs`. Notice that an update copies the supplied document fields and appends transcript text. Sending the whole transcript again would duplicate it; omitting fields can erase context. Your instructions must preserve existing fields and append only new conversation text.

### 2. Expose ordinary methods as tools

Open `InterviewSessionTool.cs`. The repository implementation and method bodies are supplied, but the starter does not expose them as tools. Add `[McpServerToolType]` above the class, then add `[McpServerTool]` attributes to its methods. The first method should look like this:

<CodeSample stage="05-mcp-state" path="src/InterviewCoach.Mcp.InterviewData/InterviewSessionTool.cs" start="[McpServerToolType]" end="    [McpServerTool(Name = &quot;get_interview_sessions&quot;" />

Use these exact tool names when annotating the other methods:

| Method | Attribute |
| --- | --- |
| `GetAllInterviewSessionsAsync` | `[McpServerTool(Name = "get_interview_sessions", Title = "Get a list of interview sessions")]` |
| `GetInterviewSessionAsync` | `[McpServerTool(Name = "get_interview_session", Title = "Get an interview session")]` |
| `UpdateInterviewSessionAsync` | `[McpServerTool(Name = "update_interview_session", Title = "Update an interview session")]` |
| `CompleteInterviewSessionAsync` | `[McpServerTool(Name = "complete_interview_session", Title = "Complete an interview session")]` |

Read the supplied parameter descriptions and improve one without changing the underlying contract. You are defining callable capabilities, not writing another database layer.

In the MCP project's `Program.cs`, find `AddMcpServer` and `MapMcp`. Those registrations make the annotated methods reachable at `/mcp`.

## If you get stuck

<Hint title="The MCP server runs but the tool list is empty">
Inspect the MCP server registrations and annotated tool class. Then check whether the agent calls `ListToolsAsync` on the intended keyed client. Registering an HTTP client alone does not attach tools to an agent.
</Hint>

<Hint title="The record changes in surprising ways">
Inspect the exact update arguments. The repository replaces document fields and appends transcript text; it does not infer which omitted fields you meant to retain. A reliable production design may use narrower update contracts.
</Hint>
