## What we are doing

Add an in-process function that returns established preparation guidance for a category. This small, deterministic tool is a teaching step. The next module replaces it with the real application's MCP tools.

## Why a function rather than another sentence in the prompt?

A model can invent a plausible preparation tip. A tool can return your application's authoritative data. The distinction becomes important when the action reads a record or changes state.

Static advice could also live in the instructions; this example intentionally keeps the function small so you can inspect the contract before adding a network protocol.

## How and where

### 1. Define the contract

In `AgentDelegateFactory.cs`, update only `CreateSingleAgent`. Add the local `GetPracticeGuidance` function, convert it with `AIFunctionFactory.Create`, and pass the resulting tools into `CreateProviderAgent`:

Read the category description and function name before running. Those descriptions help the model choose the right function and arguments. The switch is ordinary C# and remains responsible for invalid input.

### 2. Observe the boundary

Restart the agent and ask: "Use the practice guidance tool to help me prepare for the technical part of the interview."

Put a breakpoint inside `GetPracticeGuidance` or inspect the tool event in the development UI. Check the actual argument. Then compare the returned string with the assistant's explanation.

### 3. Change the source of truth

Edit the technical guidance string in code. Start a new chat and ask again. Do not change the prompt. The result should reflect the changed function output if the tool was called.

## See it work

You can point to a function execution with category `technical`, its deterministic return value, and the assistant's follow-up response. A fluent answer alone does not satisfy this checkpoint.

## Make it yours

Add one category and describe it clearly. Then request an unsupported category. Explain whether you want an explicit failure or a typed "not found" result, and what the calling agent should do next.

## If you get stuck

<Hint title="The model answered without calling the tool">
Verify the tool was passed into the agent, not just declared in code. Check that the name and description match the user's request. Ask explicitly for the tool while investigating; do not mistake that diagnostic prompt for guaranteed production routing.
</Hint>
