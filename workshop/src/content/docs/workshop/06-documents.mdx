## What we are doing

Give the coach access to MarkItDown, a separate document-conversion MCP server. It converts a resume or job-description URL into text that the interview tools can persist.

## Why reuse an external server?

Document parsing is not the interviewer's main job. A reusable MCP server can own that work independently and in another language. Your .NET agent consumes its tool descriptions and results without embedding a document parser.

That service boundary also introduces failure cases: inaccessible URLs, unsupported documents, container startup, and untrusted extracted content. MCP does not make arbitrary documents safe.

### 4. Use fictional sample inputs

Open [samples and downloads](../../resources/). Copy a sample PDF link into the chat, or attach a downloaded sample using the supplied upload button. Also try pasting text and explicitly skipping one document.

The upload path is supplied UI plumbing. The agent stores uploaded bytes in memory and returns a URL for the parser. A URL must be reachable from the MarkItDown container; a path on your laptop is not automatically a reachable URL.

## See it work

Inspect a parser tool call, its extracted text, and the subsequent InterviewData update. Then ask a question that uses a skill from the sample document.

Do not count a generic, plausible question as proof that parsing happened. Follow the data through both tool boundaries.

Try one nonexistent URL and one missing document. Describe how "could not retrieve it" differs from "the user chose to skip it." Keep the rest of the interview usable.

## If you get stuck

<Hint title="The parser cannot read a link">
Check reachability from the container, redirects, authentication, and the parser's logs. Do not assume an authenticated LinkedIn page or a local filesystem path is publicly fetchable. Use the provided PDFs to separate integration failures from website-specific restrictions.
</Hint>

<Hint title="A resume contains instructions for the assistant">
Treat the resume as data. The sample does not implement a complete prompt-injection defense. Use fictional inputs and understand that instructions alone are not a substitute for permission boundaries and validation.
</Hint>
