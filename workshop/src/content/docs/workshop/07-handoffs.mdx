## What we are doing

Split the interview into five specialists: Triage, Receptionist, Behavioural Interviewer, Technical Interviewer, and Summariser. Use Agent Framework handoffs to transfer control between them.

## Why split a working single agent?

The single-agent instructions now contain several responsibilities and two tool sets. Specialists let you focus instructions and assign tools by responsibility. They also add model calls, latency, routing decisions, and more state to reason about.

Keep the single mode available. If its behaviour is sufficient for your use case, it may be the better design.

## How and where

### 1. Assign responsibilities before writing prompts

| Agent | Responsibility | Application tools |
| --- | --- | --- |
| Triage | Choose a phase from conversation context | None |
| Receptionist | Reuse/create the record and gather materials | MarkItDown and InterviewData |
| Behavioural Interviewer | Ask behavioural questions and record feedback | InterviewData |
| Technical Interviewer | Ask technical questions and record feedback | InterviewData |
| Summariser | Summarize and complete the record | InterviewData |

Tool scoping limits what each agent can request. It does not create per-user authorization on the MCP server.

### 2. Implement the workflow factory

In `AgentDelegateFactory.cs`, replace the throwing `CreateHandOffWorkflow` method with a method returning `Workflow`. Retrieve both keyed MCP clients and their tools just as the single agent does.

Construct each specialist with the supplied `CreateProviderAgent` helper. Work through the definition below one agent at a time: compare its role, process, handoff target, and tools against the table before moving to the next.

After constructing the specialists, add the workflow builder:

Finish the method with `return workflow.SetName(key);`. The supplied `WorkflowExtensions.cs` provides the name adapter. Keep `HandoffToolResultFix.cs` and the existing `CreateFixedAgent` call: they adapt tool-result serialization for this reference version.

The normal route is Receptionist → Behavioural → Technical → Summariser. Specialists can return to Triage for an unexpected request. Routing every normal turn through Triage can repeatedly send the user back to a completed phase.

### 4. Select the mode

Set `"AgentMode": "HandOff"` in `apphost.settings.json`. Keep `"LlmProvider": "MicrosoftFoundry"`. Restart, create a new chat, and follow a short interview.

## See it work

Observe a handoff from intake into a behavioural question, then into a technical question and a summary. Inspect the active agent/tool events rather than assuming a change in tone proves a handoff.

Next, request a different phase mid-interview. Compare the path with the normal flow. Model-driven routing can fail; the graph and instructions are not a guarantee.

## Make it yours

Compare `Single` and `HandOff` with the same short fictional interview. Record one benefit, one failure mode, and one cost of specialization. Do not choose a winner solely because one uses more agents.
